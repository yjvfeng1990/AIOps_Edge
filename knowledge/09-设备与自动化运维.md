# 设备与自动化运维

> 来源：《edgeos-device-lifecycle-plan.md》《terminology.md》《device-management-system-plan.md》《edgeos-template-system-refactor-plan.md》

## 设备生命周期

四阶段：`DISCOVERED → PROVISIONING → PROVISIONED → BOUND`

- 统一设备模型 device_t：所有协议（Zigbee/Modbus/MQTT/TCP/GPIO/Relay/Screen/Audio）抽象为实例
- 设备影子（shadow）缓存最后状态；屏端只操作 `hmi_visible=true` 的子集，Web 是完整配置端

## UUID 命名规范

| 前缀 | 协议 |
|------|------|
| `zb-` | Zigbee |
| `mb-` | Modbus（RTU/TCP） |
| `mqtt-` | MQTT |
| `tcp-` | TCP 直连 |
| `relay-` / `gpio-` | 板载输出 |

## 多协议接入要点

- **Zigbee**：ZCZR Coordinator（信道 15，≤32 子设备），配网走 Web 系统设置 → Zigbee 网络 → Permit Join；ZCL 13+ Cluster 支持矩阵
- **Modbus RTU**：1 路 RS485（默认 9600 8N1，参数运行时热切），FC 01/02/03/04/05/06/0F/10；对接新设备可用 Auto485 助手（上传协议 PDF → LLM 解析 → 自动入库产品库）
- **Modbus TCP**：系统设置 → TCP Client 配置目标主机/端口/从站 ID
- **86 面板**：Modbus RTU 从站 2，非标准 8 字节主动上报帧（0x0002，走 fallback 解析），LED 控制 0x1008 位图写

## 自动化引擎

- **规则引擎**：条件-动作（如"温度 > 30 → 继电器开"），支持定时触发（整分钟匹配，依赖 NTP 已同步）
- **场景引擎**：一键批量执行设备动作组合
- **告警中心**：阈值规则（thresholds 表），产生 → 确认（已读）→ 消除（删记录）
- 事件流经 EventBus（4 优先级队列，200+ 事件/秒）驱动

## 产品库与模板

- 产品库三层模型：类别 / 品牌 / 产品；属性 + 指令（cmd_exec：value_map/scale/offset/byte_order）
- 种子数据：9 品类、3 板载内置产品、4 Modbus 协议产品、29 内置模板
- 模板 = capability_map 的 UI 预制片段，绑定时与协议 binding 合并（Merge 模式叠加 / Replace 模式替换）
- 模板存数据库，支持 Web CRUD（重构后）

## 常用运维 API（只读）

| 用途 | 端点 |
|------|------|
| 设备列表 | `GET /api/v1/devices` |
| 设备详情 | `GET /api/v1/devices/{uuid}` |
| Zigbee 网络/子设备 | `GET /api/v1/zigbee/network`、`/api/v1/zigbee/devices` |
| 规则/场景 | `GET /api/v1/rules`、`GET /api/v1/scenes` |
| 历史记录 | `GET /api/v1/history` |

设备控制（写操作）建议在 Web 后台或 API `POST /api/v1/devices/{uuid}/commands` 执行，注意操作会被审计日志记录。
